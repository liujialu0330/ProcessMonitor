# 真实 24 小时浸泡手册

> 对应 2.0.0 版本规划 §3 F-8 与 §6 质量门槛第 4 条。工具链：`tests\fixtures\soak_target.py`（被测负载）、`tools\soak_probe.py`（独立探针）、`tools\soak_verdict.py`（判定）、`tools\soak_run.ps1`（一条命令拉起与收尾）。架构口径见 `doc\代码架构说明.md` §7.9 与 §2.7，命令行说明见 `tools\README.md`。

## 1. 要回答的问题

安装版“进程监控助手”在 5 个任务、1 秒周期、26 个指标、分析页常开的条件下连续运行 24 小时：

| 门槛 | 判定口径（`soak_verdict`） |
|---|---|
| 后 20 小时私有字节增长 ≤ 30 MB，且判定不是“持续上涨” | 与分析页同一套趋势判定（`core.analysis.trend.judge`：R² ≥ 0.8、斜率置信区间不含 0、增量 ≥ 值域 5%）；增长取“拟合直线增量”与“窗口末 5% 均值 − 首 5% 均值”中较大者，后者专抓阶梯式上涨 |
| 句柄、GDI、USER、线程平稳 | 趋势判定不是“持续上涨”；判成上涨但拟合增量不超过容差（句柄 10、GDI 5、USER 5、线程 3）只提示、不算失败；数据不足算失败 |
| 采样完成率 ≥ 99.5% | 每个任务最后一次记录的 `done_cycles / planned_cycles` 都达标（C-5 数据质量列） |
| 工具全程没有退出 | 探针事件里没有 `target_exited` |
| 记录覆盖 | 记录时长 ≥ 窗口的 98%，窗口内有效样本 ≥ 应有数量的 80% |

“后 20 小时”即记录的最后 20 小时，跳过前 4 小时的预热（库缓存、字体、图表对象建立阶段）。

## 2. 环境准备

- 一台开发机，插电，磁盘剩余 ≥ 2 GB；装好安装版（`进程监控助手.exe` 与 `pmctl.exe` 同目录）。
- 开发机上有 Python 3.11 与项目依赖（负载、探针、判定都是 Python 脚本，只用标准库 + psutil）。
- **用独立数据目录**（`-DataDir`），不碰日常使用的数据：安装版同样支持 `--data-dir`。
- 设置页保持默认：“监控期间阻止电脑睡眠”开、“允许命令行与脚本控制”开。
- 关掉会抢资源的东西：杀毒全盘扫描、系统更新（暂停 1 天）、屏保与自动锁屏（锁屏由手册第 4 节手动做一次）。
- 保证 24 小时内没有预定的重启、没有笔记本合盖。

## 3. 启动

在项目根目录的 PowerShell 里一条命令：

```powershell
.\tools\soak_run.ps1 -Exe "C:\Program Files\进程监控助手\进程监控助手.exe" `
    -OutDir D:\soak\run1 -DataDir D:\soak\run1\data
```

它依次做：

1. 起 5 个负载：1 个 `leak`（每分钟 0.5 MB + 10 个句柄）、3 个 `stable`（16 MB 锯齿、60 秒周期）、1 个 `restart`（每 75 分钟退出一次，由监督进程重新拉起；加 `-CrashEvery 6` 可让每第 6 次以 0xC0000005 崩溃退出，顺带演练崩溃取证）。重启上限是 20 次，所以 24 小时内重启周期不得短于约 72 分钟（默认 `-RestartLifetimeS 4500`）。
2. 用 `-Exe` 起安装版（有窗口）；已在运行（同一数据目录）就直接用。
3. 用 `pmctl` 给 5 个负载各建一个任务：26 个指标、1 秒周期；重启负载带续接方案（`resume_on_restart`，上限 20 次）。
4. 起探针，每 10 秒记录一行，`-Hours 24`（缺省）后自动结束。

脚本几秒后返回，状态记在 `D:\soak\run1\soak_state.json`。**从此刻起记为 T+0**，把时间写在记录表里。

随后手动做一件事：在窗口里打开**分析页**，选 `leak` 任务（备注 `soak leak1`），选“私有字节”指标，保持页面常开直到结束（这是“分析页常开”的条件，图表每秒刷新）。

## 4. 中途操作（每项只做一次，都在判定窗口内）

| 时间 | 操作 | 要求 |
|---|---|---|
| T+1 h | 截图 1：分析页（含任务列表与曲线） | 留底 |
| 约 T+6 h | **休眠**：开始菜单休眠，约 2 分钟后唤醒 | 休眠 ≤ 3 分钟（休眠期间的周期计入缺采，全程缺采预算只有约 7 分钟）；记录起止时间；唤醒后确认五个任务仍在采样、分析页图表继续画；截图 2 |
| 约 T+12 h | **锁屏**：`Win+L`，约 10 分钟后解锁 | 记录起止时间；解锁后看分析页是否仍在刷新；截图 3 |
| 约 T+18 h | **切主题**：设置页“应用主题”浅色 → 深色 → 跟随系统，各停约 1 分钟，最后回到起始主题 | 每个主题下分析页截一张（截图 4、5）；观察图表与胶囊是否按主题重绘 |

操作之外不要碰电脑：不要在这台机器上跑别的重负载，也不要手动关任务或关程序。

## 5. 结束与判定

T+24 h 探针自动退出（写 `probe_stop` 事件）。然后：

```powershell
.\tools\soak_run.ps1 -Stop -OutDir D:\soak\run1
```

它会：对每个任务跑 `pmctl verdict`（结果存 `task_verdicts.txt`）→ 导出证据包到 `evidence\` → 停任务 → 停负载与探针 → 跑 `soak_verdict` 并存 `soak_verdict.txt`。你自己启动的程序不会被替你关闭。

只想重跑判定（改阈值、换窗口）时单独运行，不需要程序在运行：

```powershell
python tools\soak_verdict.py D:\soak\run1                    # 缺省窗口 20 小时
python tools\soak_verdict.py D:\soak\run1 --hours 20 --max-growth-mb 30 --min-completion 0.995
python tools\soak_verdict.py D:\soak\run1 --json
```

退出码：0 通过、1 未通过、2 输入错误。

负载侧的预期（工具链自检，不计入通过条件，但出现反例说明判定或采集有问题）：

| 任务 | 预期 `pmctl verdict` |
|---|---|
| leak1 | 持续上涨（退出码 10；私有字节与句柄数在涨） |
| stable1–3 | 平稳（退出码 0） |
| restart1 | 逐段判定；不加 `-CrashEvery` 时各段平稳或本段数据不足；加了则中途异常退出，整体“被测进程已退出”（退出码 30）并写出崩溃次数与退出码 |

## 6. 需要留下的产物

放进 `D:\soak\run1\`（并整目录打包存档，不进仓库）：

- `soak_probe.csv`、`soak_tasks.csv`、`soak_events.csv`：探针原始记录；
- `soak_verdict.txt`、`task_verdicts.txt`：判定输出；
- `evidence\*.zip`：每个任务的证据包；
- **诊断包**：结束后（程序仍开着时）设置页“数据”分组“导出诊断包”，存到 `D:\soak\run1\diag\`；
- **截图**：第 4 节的 5 张，另加结束时任务管理器“详细信息”里本工具进程的内存与句柄列；
- 记录表：T+0 实际时间、休眠与锁屏的起止时间、切主题时间、任何异常观察。

## 7. 未通过时怎么查

| 现象 | 先看 |
|---|---|
| 私有字节失败 | 逐小时看 `soak_probe.csv` 的 `private_kb`；对照诊断包里的“自身监控”判定与慢操作日志；确认是否在某个中途操作之后开始涨（休眠 / 锁屏 / 切主题） |
| 句柄 / GDI / USER 失败 | 同上看对应列；GDI / USER 往往指向界面对象（图表、胶囊）在主题切换或分析页刷新时没释放 |
| 完成率失败 | `soak_tasks.csv` 里哪个任务的 `missed_cycles` 在哪个时刻跳变，对照 `soak_events.csv` 的 `ipc_lost`（界面线程卡顿）与休眠时间；诊断包里的 `crash.log` 开头若有 `Timeout (0:00:10)!` 即界面卡死栈 |
| 工具退出 | `soak_events.csv` 的 `target_exited` 时间 + 诊断包 `crash.log` 与 `app.log` |
| 记录覆盖失败 | 探针本身被中断过（机器休眠过久、探针被杀）；重新跑整个浸泡 |

## 8. 缩短演练（15 分钟，验证工具链本身）

源码运行、无窗口，不需要安装包：

```powershell
.\tools\soak_run.ps1 -OutDir $env:TEMP\soak_drill -Hours 0.25 -Leak 1 -Stable 1 -Restart 1 `
    -LeakMbPerMin 3 -LeakHandlesPerMin 60 -RestartLifetimeS 120 -CrashEvery 3 -VerdictHours 0.2 -Wait
```

`-Wait` 让脚本等探针结束后自动收尾并判定（总时长超过 10 分钟，在交互终端里跑；别放进有 10 分钟超时的命令里，可不加 `-Wait` 而在 15 分钟后手动 `-Stop`）。预期：leak 任务被判持续上涨；restart 任务因 `-CrashEvery 3` 判被测进程退出；`soak_verdict` 对本工具自身给出通过 / 失败与理由。

判定窗口的最小跨度由趋势判定决定（10 分钟），所以演练窗口 ≥ 0.17 小时；`--hours` 更小时私有字节会判“数据不足”并失败。
