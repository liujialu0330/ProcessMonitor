# 指标采集与权限优化阶段验收

记录日期为 2026-11-15。本轮交付为未发布源码阶段归档，基于公开发布的 v2.0.2。源码版本字段仍为 2.0.2，安装包需按后续发版版本单独构建和验证。历史发布与修复结果分别见 [2.0 验收记录](2.0.0验收记录.md)和 [2.0.2 修复验收](2.0.2修复验收.md)。

## 本轮实现

- 新建任务的 CPU 指标键为 `cpu_percent_total`，按整机逻辑处理器的时间容量归一至 0～100%。单进程、进程树、同名组合计及成员采用同一口径。旧任务的 `cpu_percent` 保留按核累计数值和明确标识，旧配置或方案重新执行使用新键。
- 基本优先级展示中文名称，数据库和原始 CSV 保留 Windows 编码。`num_ctx_switches_voluntary` 的名称改为“上下文切换”，表示当前存活线程的切换次数总和，包含主动等待与被抢占。线程退出可能导致读数回落。
- 上下文切换平均速率依据全量原始相邻样本的有效时间加权，跳过计数回落、采集空洞和重启续采边界。图表抽稀及明细行数上限独立于平均值。断点通过物化表和索引连接处理。
- 指标实际返回权限不足时，按任务合并提示，提供保存任务后管理员重启及继续采集可用指标。勾选 USS 时显示条件性说明，管理员窗口标注身份。
- 提权候选核验进程句柄、创建时间、当前用户 SID 和管理员令牌。旧实例确认候选就绪后，在可撤销采集屏障中保存样本、成员、质量、设置与界面状态，再提交交接记录。候选等待旧实例退出后访问数据库。
- 交接保留任务 ID、开始时间、历史样本、基线与打点、暂停、等待目标重启、等待启动、启动关联、方案、表单及卡片趋势。进程组的虚拟累计合计、成员累计、顺序和截断状态一并保留，实例差分起点重建，空档增长不计入。被测目标重启续接也保留累计总量。
- 提交前取消或准备失败时原实例继续工作。已提交记录可由普通 GUI 启动恢复，后台启动遇到待恢复交接时返回 6 并保留记录。管理员 IPC 实例要求危险命令客户端具备相应完整性级别。

## 归档和清理

本地归档位于 `context/02_项目维护/归档/2026-11-15_指标与提权阶段/`。其中保留逐项采集对照、窗口交接证据、SQLite 数据、自检报告、最终功能回归、历史安装包及构建快照。文件清单记录大小与 SHA-256，压缩包在移除展开目录前校验内容。

清理范围包括 Python 与 pytest 缓存、可重新生成的视觉测试截图、PyInstaller 工作文件、版本资源和已校验压缩归档的展开程序目录。运行证据与历史维护材料按阶段归档。代码、测试夹具、锁定依赖、打包配置及正式用户数据属于保留范围。

实际移除 1327 个生成文件，原始合计 697,960,714 字节。移动归档 301 个文件，合计 301,439,562 字节。两份构建 ZIP 合计 227,528,453 字节，均通过 CRC、条目数量与逐文件 SHA-256 校验。以上均为文件逻辑大小。

仓库提交包括源码、测试与公开文档。数据库、安装包、构建目录和本地上下文由既有排除规则管理。

## 验证边界

- 本机管理员提升策略直接批准提权，真实 UAC 取消交互待具备提示窗口的环境复核。取消路径已有 Windows 错误码 1223 及 QThread 协调回归。
- 本轮执行功能回归、入口自检和上述查询规模核验。完整性能基准、真实 24 小时浸泡、完整设备/多屏专项和多人内测沿用各自记录的实际执行状态。
- 后续安装包发布需验证最终版本、安装升级及公网更新链路，体积目标为安装包 ≤ 100 MB、程序目录 ≤ 350 MB，均按十进制计算。
