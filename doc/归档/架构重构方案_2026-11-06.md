## 2. 总体结论

### 2.1 现状评价

做得好、必须保留的部分：

- 四层依赖方向基本单向，没有循环导入，页面之间不互相引用。
- 采集失败"不记 0"是全链路契约；CPU 预热、PID 复用识别、单调时钟调度设计正确。
- 工作线程不碰控件；历史页自动刷新已经走后台线程并带请求序号防过期。
- 数据库迁移在单事务里执行，迁移前 checkpoint + 文件备份，分桶降采样保留每桶极值。
- `ui/formatting.py`、`core/export.py`、`utils/metrics.py` 是纯函数，分得干净。
- 退出路径有明确的不变式（`代码架构说明.md` §6），且有测试守住。
- 430 个自动化用例，覆盖迁移、调度、页面流程、导出、单实例。

### 2.2 核心问题（五条）

1. **"上帝模块"**：`history_page.py`（1457 行，9 类职责）、`database.py`（1354 行，6 类职责）、`monitor_page.py`（762 行）。改一处要通读全文，测试只能靠调私有方法。
2. **跨层契约靠字符串和私有属性名维系**：停止原因、不可用原因、任务状态都是中文字面量在 core 与 ui 之间比对；主窗口关窗用 `getattr(page, '_xxx_worker')` 读页面私有属性收线程。任何改名都静默失效。
3. **同一逻辑写两份**：历史页同步加载与后台刷新各实现一套查询编排；历史页与导出页各实现一套任务下拉；"任务是否运行中"有三种口径；指标元数据分散在 6 个以上文件。
4. **组合根缺位**：`Database`、`MonitorManager` 由 `MainWindow` 构造并下发，各页面和 core 都保留"自建兜底"；`main.py` 只做了一半启动工作；路径解析在 `config.py`、`utils/logger.py`、`app_config.py` 各算一遍（日志目录不认 `PROCESS_MONITOR_DATA_DIR`）。
5. **产品层：方法论没有落到界面上**。PRD 的核心方法是"基线 → 打点 → 分轮看增量"，但所有统计只按时钟范围算，打点只画竖线；"增速"在 11 秒数据上外推出 "+28.6 GB/小时" 并作为最醒目数字展示；多指标只能逐个切换；证据交付要跨三个页面约 20 次点击。

此外发现 **9 个已核实的功能缺陷**（§4.1），与重构无关，应先修。

### 2.3 重构的边界

- **不换框架、不加依赖**：仍是 PyQt5 + qfluentwidgets + pyqtgraph + SQLite。
- **不改数据库文件格式的兼容性**：新增表/列走 v4 迁移，旧库可读。
- **不一次性重写**：每阶段可独立合入、独立发布，测试全程绿。
- **不引入事件总线/框架级 MVVM 库**：页面间只有 3 条连线，用信号即可。

| # | 缺陷 | 证据 | 后果 |

### 6.4 设计规范要点

- **间距**：4px 网格；页边距 24；区块间距 24；卡片间距 8–12；卡片内边距 16；控件间距 8；标签到字段 12；所有卡片左右缘对齐。
- **字号**：Caption 12（标签、元信息）；Body 14；Body Strong 14 Semibold（卡片/区块标题）；Subtitle 20 Semibold（页面标题、关键数值）。数字统一用 UI 字体（等宽数字），同一单位固定 2 位小数、右对齐；等宽字体只用于明细表时间列与坐标轴。`SectionTitleLabel` 要么用起来要么删掉。
- **颜色角色**：文字三档；强调色只用于主按钮、选中态、图表曲线；状态色 运行中 `#0F7B0F/#6CCB5F`、已暂停 `#9D5D00/#FCE100`、异常结束 `#C42B1C/#FF99A4`、正常结束用三级文字色；图表背景透明继承卡片色（删掉 `chart_theme.py:19` 的 `#2b2b2b`）；打点线用注意色；增长方向只用箭头不着色。
- **按钮层级**：每区域最多一个主按钮；对话框主按钮必须是"安全且推荐"的操作，破坏性操作普通样式、文案写动词（删除/停止/清理）、默认焦点在取消；低频操作用透明图标按钮 + tooltip；图标必须与动作一致（停止用自绘 16px 实心方块 SVG，不用 CANCEL）。
- **InfoBar 规则**：界面上能直接看到结果时不弹成功提示（如任务启动）；成功 ≤ 2 秒；警告 5 秒可关闭；错误常驻并带操作按钮；表单校验放字段旁；每页同一时间最多一条，同类合并；重要异步事件常驻 + 卡片状态 + 后台时托盘通知。
- **时间格式**：列表项 `MM-DD HH:mm`；明细与悬停 `MM-DD HH:mm:ss`；当天结束时间只写 `HH:mm:ss`；完整年份只在导出摘要与 tooltip。数字与单位之间统一加空格。
- **加载反馈**：统一为卡片内 `IndeterminateProgressBar`；超过 300 ms 的操作必须有忙碌态。
- **最小窗口**：800×600（PRD）。小窗口下统计条在视口 ≥ 760 保持一行 6 格；"趋势/明细"、悬停读数、保存/复制合并到图表卡标题行；图表最小高度 220，占满剩余空间。
- **键盘**：搜索框回车直接选中；备注框回车 = 开始监控；F5 刷新；Ctrl+F 聚焦搜索；对话框回车 = 安全操作；`setTabOrder` 显式声明。

### 10.3 术语

- **基线**：预热稳定后的第一个打点，所有"较基线"统计的起点。
- **打点区间**：相邻两个打点之间的时间段；"每轮增量"即该区间内指标的终值减起值。
- **空洞**：相邻样本间隔超过 2.5 倍采集周期的时间段（暂停、采集失败、休眠）。
- **水位量 / 累计计数 / 峰值**：指标的三种 `kind`，决定显示与外推方式。
- **门面（Facade）**：`Database` 类在拆分期间保留原接口，内部委托给仓储模块。
