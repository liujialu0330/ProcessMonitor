## 1. 产品概述

### 1.1 产品定位
进程监控助手是一款专业的Windows桌面应用程序，旨在为软件测试人员提供强大的进程性能监控工具，帮助发现和诊断内存泄漏、CPU占用异常等性能问题。

### 1.2 产品目标
- 提供实时的进程性能指标监控
- 记录并可视化历史监控数据
- 支持“基线—打点—变化量/增长速度”的泄漏排查方式：以量化的增长趋势取代肉眼读数
- 简化测试流程，提高测试效率
- 提供现代化、易用的用户界面

### 1.3 目标用户
- **主要用户**：软件测试工程师
- **次要用户**：性能测试工程师、开发工程师
- **使用场景**：
  - 桌面应用性能测试
  - 内存泄漏检测
  - CPU占用分析
  - 长时间运行稳定性测试

## 2. 核心功能需求

### 2.1 实时监控功能

#### 2.1.1 进程选择
**需求描述**：用户可以通过多种方式选择要监控的进程

**功能要求**：
- 支持通过PID直接输入选择进程
- 支持从系统进程列表中选择进程，下拉框可按进程名或PID关键字搜索
- 进程列表支持刷新，获取最新运行进程
- 显示进程名称和PID信息
- 不默认选中任何进程，必须由用户明确选择或输入
- 对仍在监控中的同一PID再次创建任务时，弹出确认后才创建
- 可填写“测试备注”（可选，最多100字），随任务保存，用于区分各次测试

**优先级**：P0（必须）

#### 2.1.2 指标选择
**需求描述**：提供多种性能指标供用户选择监控，支持单个任务同时勾选多个指标（多指标监控）

**功能要求**：
- 点击"选择指标"按钮弹出多选对话框，指标按分类分组展示
- 每个分类附带三态复选框，支持该分类下"全选/部分选中/取消全选"
- 已选指标数量与名称摘要实时显示在按钮旁（内容过长时省略显示，完整内容通过提示条查看）
- 提供“泄漏排查预设”按钮，一键勾选私有字节、句柄数、GDI对象数、USER对象数、线程数；监控页默认即为该预设，并记住用户上次的选择
- 每个指标附一句说明（含义与适用场景），悬停即可查看；至少需勾选1个指标才能确认
- 一个监控任务可同时采集多个指标，采集时共用同一采集周期与同一时间戳

**支持的指标**（共27个，按分类分组）：

| 分类 | 指标名称 | 说明 | 单位 |

| 内存 | 私有字节峰值 | 私有字节的峰值 | KB |
| 内存 | 分页池 | 进程使用的分页池内存 | KB |
| 内存 | 分页池峰值 | 分页池使用量的峰值 | KB |
| 内存 | 非分页池 | 进程使用的非分页池内存 | KB |
| 内存 | 非分页池峰值 | 非分页池使用量的峰值 | KB |
| 内存 | 页面错误 | 累计发生的页面错误次数 | 次 |
| 内存 | 唯一集大小 | 进程独占、不可与其他进程共享的物理内存（USS） | KB |
| CPU | CPU使用率 | 进程CPU占用百分比 | % |
| CPU | CPU用户时间 | 进程在用户态累计消耗的CPU时间 | 秒 |
| CPU | CPU系统时间 | 进程在内核态累计消耗的CPU时间 | 秒 |
| CPU | 优先级 | 进程的调度优先级 | 无 |
| 系统资源 | 线程数 | 进程创建的线程数量 | 个 |
| 系统资源 | 句柄数 | 进程打开的句柄数量（Windows） | 个 |
| 系统资源 | GDI对象数 | 进程创建的 GDI 对象数量（Windows，界面绘图资源泄漏的判断依据） | 个 |

| IO操作 | IO其他次数 | 除读写外其他I/O操作累计次数 | 次 |

**优先级**：P0（必须）

#### 2.1.3 采集周期配置
**需求描述**：用户可以自定义数据采集的时间间隔

**功能要求**：
- 采用数值输入框（微调框）直接输入采集周期，不再提供固定预设选项
- 输入范围：1~3600秒的整数
- 默认采集周期为1秒
- 超出范围时自动限制在合法区间内

**优先级**：P1（重要）

#### 2.1.4 多任务监控
**需求描述**：支持同时监控多个进程的不同指标

**功能要求**：
- 最多同时监控5个任务；配额只计运行中的任务，已结束但未关闭的卡片不占用配额
- 每个任务独立配置监控指标和采集周期
- 达到任务上限时给出明确提示
- 支持单独暂停/恢复、停止某个监控任务；停止前需确认，避免误点

**约束条件**：
- 最大并发任务数：5个
- 防止系统资源过度占用

**优先级**：P0（必须）

#### 2.1.5 实时数据显示
**需求描述**：以卡片形式实时显示监控数据

**显示内容**：
- 进程名称、PID、测试备注和任务状态（运行中/已暂停/已结束）
- 各监控指标的当前值（带单位格式化，多指标以网格形式逐项排列）及“较开始”变化量（相对本任务首个有效值）
- 首个指标“任务开始至今”的迷你趋势图（点数过多时等跨度抽稀，纵轴设最小跨度，避免微小抖动被放大）
- 已记录的采集次数
- 操作：打点、暂停/恢复、停止

**任务结束后**：卡片保留并切换为“已结束”，保留最后的数值与趋势，提供“查看历史”（跳转历史页并选中该任务）、“重新监控”（沿用进程、指标、周期与备注新建任务；按进程名查找运行中的进程，不含本程序自身，找到多个或找不到时由用户在进程框中选择）和“关闭”（移除卡片）。被测进程崩溃或退出等非用户停止的情形，弹出显眼的提示条，窗口在后台时补一条托盘气泡。

**更新频率**：根据采集周期实时更新

**优先级**：P0（必须）

#### 2.1.6 采集失败语义
**需求描述**：采不到的指标不能被记成0，否则会被误读为真实数据

**功能要求**：
- 某指标本周期无法采集时，该指标不写入数据（留空），其他指标照常记录
- 任务卡片将该指标显示为“不可用”，并提示一次原因（每个指标每个任务只提示一次）
- 未以管理员运行时，对更高权限进程只有“唯一集大小”无法采集；以管理员身份运行可采集全部指标
- 其他会话的进程（如系统服务）的GDI/USER对象数显示“不支持”（提权也无法采集，与权限不足区分）
- 历史图表与CSV对缺失值按空处理
- 进程不存在，或PID已被另一个进程复用（比对进程创建时间）时，任务以“进程已终止”结束

**优先级**：P0（必须）

#### 2.1.7 打点与测试备注
**需求描述**：为长时间监控中的关键操作留下时间标记，便于在历史曲线上对应到具体测试动作

**功能要求**：
- 运行中的任务可随时打点：弹出输入框，默认标签“标记 N”，最多40字
- 打点以当前时间落库，历史图表上显示为带标签的竖线；悬停时提示所处的打点区间（如“打点「基线」后 3分钟”）
- 打点随CSV导出写入末列“打点”
- 测试备注在创建任务时填写，显示在任务卡片、历史页与导出页的任务列表中

**推荐用法**：选进程 → 使用默认预设 → 预热到稳定后打点“基线” → 每轮操作后打点 → 在历史页查看“变化量”与“增长速度”

**优先级**：P1（重要）

### 2.2 历史数据功能

#### 2.2.1 数据持久化
**需求描述**：所有监控数据自动保存到本地数据库

**功能要求**：
- 使用SQLite数据库存储，启用WAL（Write-Ahead Logging）模式提升读写并发稳定性
- 采用批量保存接口写入数据（当前批大小配置为1条，即每次采集立即落盘，以保证历史页面能实时看到最新数据）
- 数据落库失败时自动重试：采集缓冲保留待重试数据（上限1000条，超出丢弃最旧数据），连续失败达到阈值时提示用户一次（v1.2.0）
- 自动管理数据库连接
- 支持长时间监控数据存储

**优先级**：P0（必须）

#### 2.2.2 历史任务查看
**需求描述**：用户可以查看所有监控任务的历史记录

**功能要求**：
- 显示所有包含数据的任务（含运行中和已停止），任务列表在历史数据页与导出数据页统一为"有数据即显示"，不再按进程名等规则额外隐藏（v1.2.0：此前被隐藏的短时/测试任务将重新显示，可通过删除按钮清理）
- 任务下拉项显示：进程名、PID、开始时间、时长、备注（运行中任务标注“运行中”）；悬停显示完整信息
- 支持任务选择和切换
- 多指标任务额外提供"指标"下拉框，用于切换查看某一项指标的图表与数据
- 筛选区在宽窗口采用两行紧凑布局，在窄窗口自动重排控件，避免标签、下拉框和时间范围互相挤压
- 默认展示“全部”数据（泄漏判断需要看从开始至今的整体趋势）；支持10分钟、1小时、6小时、24小时和全部范围切换
- 所选任务仍在运行时，图表与统计在页面可见期间自动刷新，刷新间隔随数据量自适应（数据越多间隔越长）；任务结束后自动同步最终数据

**优先级**：P0（必须）

#### 2.2.3 数据可视化
**需求描述**：以图表形式展示监控数据趋势

**功能要求**：
- 折线图显示数据随时间变化
- X轴：真实日期时间，根据范围与采样密度控制刻度数量
- Y轴：指标值（自动缩放，按量级自适应显示KB/MB/GB/TB等单位，刻度按显示单位取整；计数类指标使用整数刻度；曲线过于平直时设纵轴最小跨度，避免微小抖动被放大成满幅波动）
- 打点以竖线叠加在图表上
- 图表交互：缩放、平移
- 多指标任务切换"指标"下拉框后，图表同步刷新为所选指标的数据
- 数据量较大时，图表数据由数据库端按分桶（最多2000桶，每桶取最小/最大值两点）降采样后返回，最多约4000个点，保留波峰波谷不失真；图表控件叠加峰值抽稀与视口裁剪进一步优化渲染（v1.2.0）
- 图表与明细分为“趋势/明细”两个子视图；统计条常驻展示起点、当前、变化量（绝对值与百分比）、增长速度（每小时，对所选范围全部数据做最小二乘线性回归；持续为正说明在持续上涨）、最小、最大，删除任务与原始值等低频信息按需呈现
- 图表可导出为PNG或复制到剪贴板，配色跟随深浅色主题

**优先级**：P0（必须）

#### 2.2.4 数据表格
**需求描述**：以表格形式展示详细数据点

**功能要求**：
- 默认列：时间、格式化值；“原始值”列可从“更多”菜单按需显示
- 只显示最近2000次采集的数据点（大数据量任务性能优化，v1.2.0；导出数据不受此限制，仍为全量），表格上方标注“显示最近 2,000 条 / 共 N 条”
- 按时间倒序排列（最新在前）
- 支持滚动查看
- 禁止编辑
- 多指标任务切换"指标"下拉框后，表格同步刷新为所选指标的数据

**优先级**：P1（重要）

#### 2.2.5 任务数据管理
**需求描述**：用户可在历史数据页面手动清理不再需要的监控任务数据，应用也可选择性地在启动时自动清理过期数据（v1.2.0）

**功能要求**：
- 历史数据页面在“更多”菜单提供“删除此任务数据”，点击后二次确认，确认后删除该任务及其全部数据点
- 任务处于运行中状态时禁用“更多”菜单中的删除操作（需先停止任务），避免删除正在写入的数据引发竞态；删除时一并删除该任务的打点
- 设置页的数据库清理与压缩与运行中任务互斥：有任务运行时不可用，清理期间不能新建或启动任务
- 支持可选的启动自动清理：通过配置项设定数据保留天数，默认0表示禁用；启用后仅清理已停止且早于保留期限的任务及其数据点，且保证在孤儿任务状态校正完成之后执行，避免误删刚异常退出的任务

**优先级**：P2（增强）

### 2.3 数据导出功能

#### 2.3.1 任务选择导出
**需求描述**：用户可以选择特定的监控任务进行数据导出

**功能要求**：
- 从下拉列表选择要导出的任务
- 显示任务详细信息（进程名、PID、监控指标——多指标显示项数与名称、开始/结束时间、采集次数与数据点总数、任务状态）
- 支持任务列表刷新
- 仅显示包含数据的任务
- 任务选择、任务摘要、保存位置和导出动作合并为自上而下的单一连续流程，避免多个等权卡片分散注意力
- 切换任务时重置默认文件名；任务信息中的数量使用千分位显示

**优先级**：P0（必须）

#### 2.3.2 CSV文件导出
**需求描述**：将监控数据导出为CSV格式文件，多指标任务导出为宽表格式（每次采集一行，各指标各占一列）

**功能要求**：
- 支持文件保存路径选择
- 智能文件命名：`{进程名}_{PID}_{开始时间}.csv`（去掉`.exe`后缀与文件名非法字符）；目标文件已存在时，覆盖前需确认
- CSV格式要求：
  - 使用UTF-8 BOM编码（确保Excel正确打开中文）
  - 宽表结构：前三列固定为"时间、进程名称、PID"，其后每个监控指标各占一列，列头格式为"指标名(单位)"，末列为“打点”（打点写在时间不早于打点时刻的第一行，同一行多个打点以“; ”连接，晚于最后一次采集的并入最后一行）
  - 每行对应一次采集（同一时间戳的多指标数据合并为一行），若某指标在该时间戳缺失数据则该列留空
  - 时间格式：`YYYY-MM-DD HH:MM:SS`
  - 指标数值保留4位小数
- 导出在后台线程中执行，不阻塞界面操作，支持导出中途取消（v1.2.0）；先写入同目录临时文件，成功后才替换目标文件，取消或失败只清理临时文件，不会损坏已有文件
- 导出成功后不自动抢占焦点打开资源管理器；在成功提示中提供“打开文件夹”，由用户明确触发
- 完善的错误提示和状态反馈

**优先级**：P0（必须）

#### 2.3.3 数据完整性
**需求描述**：确保导出的数据完整准确

**功能要求**：
- 导出任务的所有采集记录（含全部已选指标）
- 数值保留4位小数，缺失数据留空而非填0
- 列头本身标注指标名称与单位，无需额外的单位列
- 包含任务元信息（进程名称、PID）

## 6. 数据模型

### 6.1 监控任务（MonitorTask）
自v1.1.0起支持多指标监控，原单值 `metric_type` 字段已改为字符串列表 `metric_types`：
```python
{
    "task_id": "UUID字符串",
    "pid": "进程ID",
    "process_name": "进程名称",
    "metric_types": ["指标类型1", "指标类型2", "..."],  # 指标类型列表，支持多指标
    "interval": "采集间隔(秒)",
    "start_time": "开始时间",
    "end_time": "结束时间(可空)",
    "status": "running | stopped",
    "note": "测试备注(可空串)",
    "sample_count": "已采集次数(同一周期多指标算一次)",
    "last_sample_at": "最后一次采样时间(可空)"
}
```

### 6.2 数据点（DataPoint）与打点（Marker）
数据点带 `metric_type` 字段，标记该数据点归属于任务的哪一项指标；采集失败的指标不产生数据点：
```python
{
    "task_id": "所属任务ID",
    "timestamp": "时间戳",
    "value": "指标值(浮点数)",
    "metric_type": "指标类型"
}
```
打点用于在曲线上标注测试动作：
```python
{
    "task_id": "所属任务ID",
    "timestamp": "打点时间",
    "label": "标签文字"
}
```

### 6.3 数据库结构与迁移

**表结构（Schema v3）**：
- `tasks` 表：`metric_type` 列存储 JSON 数组文本（如 `["memory_rss","cpu_percent"]`），对应 `metric_types` 字段；另有 `note`、`sample_count`、`last_sample_at`。历史页/导出页按 `sample_count > 0` 判断“有数据的任务”，避免逐任务统计数据点
- `data_points` 表：`task_id`、`timestamp`、`value`、`metric_type`（允许为 NULL，兼容升级前的历史数据），仅保留一个复合索引 `(task_id, metric_type, timestamp)`，覆盖按任务/指标/时间范围的过滤、排序与首尾点查询
- `task_markers` 表：`id`、`task_id`、`timestamp`、`label`、`created_at`，索引 `(task_id, timestamp)`
- 时间戳一律以 ISO 文本存储和比较
- 外键约束未启用，删除任务时手工级联删除其数据点与打点
- 每个数据库连接开启时统一设置 `WAL` 日志模式、`busy_timeout=5000ms`、`synchronous=NORMAL`，提升并发读写下的稳定性（v1.2.0）

**自动迁移机制**：
- 数据库使用 `PRAGMA user_version` 标记 Schema 版本（当前为 v3），启动时低于当前版本则按 v0→v1→v2→v3 链式迁移：
  - v0→v1：补充 `data_points.metric_type` 并按任务原有指标回填，`tasks.metric_type` 由裸字符串转换为 JSON 数组
  - v1→v2：把 `memory_vms`、`memory_pagefile` 并入 `memory_private`，同一时间戳的重复数据点去重
  - v2→v3：`tasks` 增加 `note`、`sample_count`、`last_sample_at` 并回填；新建 `task_markers`；清理孤儿数据点、回填 NULL 的指标类型；索引收敛为 `(task_id, metric_type, timestamp)`
- 迁移前先对旧库做一次 WAL checkpoint，再将数据库文件备份为同目录下的 `monitor.db.bak_v{原版本}`，原始数据永不删除
- 整条迁移链在同一个显式事务中执行，任一步失败整体回滚；失败后先从备份文件还原并重试一次，两次仍失败则将损坏的数据库文件改名保留（形如 `monitor.db.broken_时间戳`）、新建空库
- 迁移结果分三种明确状态，分别对应不同的主界面提示（v1.2.0）：
  - **迁移失败已还原**（`migration_failed`）：两次迁移均失败，已还原旧数据，提示用户本次会话新数据无法保存，需重启重试
  - **数据已重置**（`data_reset`）：还原备份也失败，损坏库已改名保留，应用以新建空库运行，提示用户历史数据已移至 `monitor.db.broken_*`
  - **迁移已中止**（`backup_aborted`）：迁移前备份本身失败（如磁盘空间不足），直接中止迁移、旧库原样保留未做任何改动，提示用户释放磁盘空间后重启
- 整个迁移流程每次应用运行只尝试一次，避免同一进程内因反复实例化数据库对象而重复触发备份
- 每次启动另外执行：校正遗留的“运行中”任务、重算采样计数为0但有数据点的任务（回退旧版本再升级后的兜底）

## 7. 系统流程

### 7.1 创建监控任务流程
```
选择进程（或输入PID）→ 确认指标（默认泄漏排查预设）→ 设置周期、填写备注
    ↓
点击"开始监控"（同PID已在监控则二次确认）
    ↓
检查运行中任务数量限制与数据库维护状态
    ↓
创建监控任务(QThread)，任务行落库
    ↓
按单调时钟截止时间循环：采集 → 落库 → 更新卡片
    （采不到的指标留空并提示不可用）
```

### 7.2 停止监控任务流程
```
用户点击"停止"并确认
    ↓
置停止标志并唤醒工作线程（界面不等待）
    ↓
工作线程内：保存剩余数据 → 写入已停止状态 → 发出停止信号
    ↓
卡片切换为"已结束"（查看历史 / 重新监控 / 关闭），释放任务线程对象
```

### 7.3 查看历史数据流程
```
切换到历史数据页面（默认"全部"范围）
    ↓
加载有数据的任务列表（运行中任务标注"运行中"）
    ↓
用户选择任务与指标
    ↓
数据库端聚合统计 + 分桶降采样 + 读取打点
    ↓
绘制趋势图与打点竖线，填充统计条与明细表
    ↓
任务运行中：页面可见时自动刷新
```

### 7.4 导出流程
```
选择任务 → 确认默认文件名（切换任务会重置）→ 选择保存位置（已存在则确认覆盖）
    ↓
后台线程流式读取数据点与打点，写入同目录临时文件
    ↓
成功：替换目标文件，提示并可打开文件夹；取消/失败：删除临时文件
```

### 7.5 关闭窗口流程
```
关闭窗口
    ↓
设置了"关闭时最小化到托盘" → 隐藏到托盘，监控继续
    ↓
有运行中任务 → 询问：停止并退出 / 最小化到托盘 / 取消
    ↓
停止并退出：等待全部任务收尾落库 → 清理后台线程 → 退出
（系统注销/关机时跳过询问，直接退出）
```

## 8. 异常处理

### 8.1 进程不存在
- **场景**：用户输入的PID不存在或无法访问
- **处理**：显示错误提示，禁止创建任务

### 8.2 进程已终止
- **场景**：监控过程中进程意外终止，或PID已被另一个进程复用
- **处理**：自动停止监控任务，保存已采集数据；任务卡片保留并标为已结束，弹出提示条（窗口在后台时补托盘气泡）

### 8.3 数据库异常
- **场景**：数据库文件损坏或权限不足
- **处理**：显示错误信息，尝试重新初始化数据库
- **场景**：单次数据保存失败（磁盘瞬时繁忙等）
- **处理**：自动保留待落库数据并在下一采集周期重试，不立即丢弃；连续失败达到阈值时提示用户一次（v1.2.0）
- **场景**：旧版本数据库升级迁移失败（详见6.3节）
- **处理**：自动从迁移前备份还原并重试一次；三种最终结果对应三种明确的主界面提示——迁移失败已还原（提示重启重试）、数据已重置（提示历史数据已移至`.broken_*`文件）、迁移已中止（提示释放磁盘空间后重启）（v1.2.0）

### 8.4 任务数量超限
- **场景**：用户尝试创建第6个运行中的监控任务
- **处理**：显示警告提示，禁止创建

### 8.5 指标不可用
- **场景**：权限不足（如未以管理员运行时采集更高权限进程的唯一集大小）、进程正在退出，或指标对该进程不适用（其他会话进程的GDI/USER对象数）
- **处理**：该指标不写入数据，卡片显示“不可用”并提示一次原因（权限不足时建议以管理员运行）；其他指标不受影响

### 8.6 更新包无法校验
- **场景**：新版本的安装包缺少SHA-256摘要，或下载后校验不一致，或下载地址不在官方域名内
- **处理**：不安装；缺少摘要时提示“请前往发布页手动下载”，校验不一致时删除已下载文件并报错

## 附录：术语表

| 术语 | 解释 |
|------|------|
| PID | Process ID，进程标识符 |
| RSS | Resident Set Size，工作集内存 |
| 私有字节 | Private Bytes，进程独占的已提交内存（PrivateUsage，等同任务管理器"提交大小"；psutil 的 vms / pagefile / private 在 Windows 上数值相同） |
| GDI/USER对象 | Windows界面资源：GDI对象（画笔、位图、字体等绘图资源）与USER对象（窗口、菜单、光标等），数量持续增长通常意味着界面资源泄漏 |
| 打点 | 在监控过程中以当前时间为任务添加的带标签的时间标记 |
| 基线 | 被测程序预热到稳定状态时的第一个打点，用于与后续各轮操作后的数值对比 |
| USS | Unique Set Size，进程独占、不可与其他进程共享的物理内存 |
| CPU使用率 | 进程占用CPU的百分比 |
| 句柄 | Windows系统资源的引用 |
| IO | Input/Output，输入输出操作 |
| Qt信号槽 | Qt框架的事件通信机制 |
| QThread | Qt的线程类 |
| SQLite | 轻量级关系型数据库 |
