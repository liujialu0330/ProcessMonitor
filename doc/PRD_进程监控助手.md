## 1. 产品概述

### 1.1 产品定位
进程监控助手是一款专业的Windows桌面应用程序，旨在为软件测试人员提供强大的进程性能监控工具，帮助发现和诊断内存泄漏、CPU占用异常等性能问题。

### 1.2 产品目标
- 提供实时的进程性能指标监控
- 记录并可视化历史监控数据
- 支持“基线—打点—每轮增量/增速判定”的泄漏排查方式：以量化的增长趋势与明确的判定结论取代肉眼读数，并可一键导出报告
- 简化测试流程，提高测试效率
- 提供现代化、易用的用户界面

### 1.3 目标用户
- **主要用户**：软件测试工程师
- **次要用户**：性能测试工程师、开发工程师
- **使用场景**：
  - 桌面应用性能测试
  - 内存泄漏检测
  - CPU占用分析
  - 长时间运行稳定性测试

## 2. 核心功能需求

### 2.1 实时监控功能

#### 2.1.1 进程选择
**需求描述**：用户可以通过多种方式选择要监控的进程

**功能要求**：
- 支持通过PID直接输入选择进程
- 支持从系统进程列表中选择进程，下拉框可按进程名或PID关键字搜索
- 进程列表支持手动刷新（按钮或F5），页面显示、窗口重新激活时自动刷新；Ctrl+F聚焦进程搜索框
- 显示进程名称和PID信息
- 不默认选中任何进程，必须由用户明确选择或输入
- 对仍在监控中的同一PID再次创建任务时，弹出确认后才创建
- 可填写“测试备注”（可选，最多 2000 个 Unicode 字符），随任务保存，用于区分各次测试；方案导入后编辑保存不截断
- 等待进程启动：勾选“等待进程启动后自动开始”并点开始后，任务位置先显示占位卡“等待 xxx.exe 启动…”（可取消）；按进程名每秒查找一次，进程出现即以所选指标、周期与备注自动开始监控（用于被测程序需要从启动阶段开始观察的场景）。勾选后显示等待超时输入，可留空不限时，或填写 1 秒至 30 天（支持小数秒）；方案往返保留该值

**优先级**：P0（必须）

#### 2.1.2 指标选择
**需求描述**：提供多种性能指标供用户选择监控，支持单个任务同时勾选多个指标（多指标监控）

**功能要求**：
- 点击"选择指标"按钮弹出多选对话框，指标按分类分组展示
- 每个分类附带三态复选框，支持该分类下"全选/部分选中/取消全选"
- 已选指标数量与名称摘要实时显示在按钮旁（内容过长时省略显示，完整内容通过提示条查看）
- 提供“泄漏排查预设”按钮，一键勾选私有字节、句柄数、GDI对象数、USER对象数、线程数；监控页默认即为该预设，并记住用户上次的选择
- 每个指标附一句说明（含义与适用场景），悬停即可查看；至少需勾选1个指标才能确认
- 一个监控任务可同时采集多个指标，采集时共用同一采集周期与同一时间戳

**支持的指标**（共26个，按分类分组）：

| 分类 | 指标名称 | 说明 | 单位 |

| 内存 | 工作集内存 | 进程实际占用的物理内存（RSS/WSET） | KB |

| 内存 | 私有字节峰值 | 私有字节的峰值 | KB |

| 内存 | 分页缓冲池峰值 | 分页缓冲池使用量的峰值 | KB |
| 内存 | 非分页缓冲池 | 进程使用的内核非分页缓冲池（任务管理器同名列） | KB |

| CPU | CPU使用率 | 进程CPU占用百分比 | % |

**优先级**：P0（必须）

#### 2.1.3 采集周期配置
**需求描述**：用户可以自定义数据采集的时间间隔

**功能要求**：
- 采用数值输入框（微调框）直接输入采集周期，不再提供固定预设选项
- 输入范围：1~3600秒的整数
- 默认采集周期为1秒
- 超出范围时自动限制在合法区间内

**优先级**：P1（重要）

#### 2.1.4 多任务监控
**需求描述**：支持同时监控多个进程的不同指标

**功能要求**：
- 最多同时监控5个任务；配额只计运行中的任务，已结束但未关闭的卡片不占用配额
- 每个任务独立配置监控指标和采集周期
- 达到任务上限时给出明确提示
- 支持单独暂停/恢复、停止某个监控任务；停止前需确认，避免误点

**约束条件**：
- 最大并发任务数：5个
- 防止系统资源过度占用

**优先级**：P0（必须）

#### 2.1.5 实时数据显示
**需求描述**：以卡片形式实时显示监控数据

**显示内容**：
- 身份行：进程名称、状态胶囊（运行中 / 已暂停 / 已结束 / 异常结束，全应用统一的四个状态词）、PID、采集周期、已运行时长；测试备注
- 各监控指标的当前值（带单位格式化，多指标以网格形式逐项排列）及变化量：已打基线时为“较基线”（基线值取基线打点后5个样本的中位数），否则为“比开始时（N 分钟前）”；指标格排成6列时改为短文案“较开始 +X”，完整说明见悬停提示
- 首个指标“任务开始至今”的迷你趋势图，带打点刻度（点数过多时等跨度抽稀，纵轴设最小跨度，避免微小抖动被放大）
- 已记录的采集次数
- 操作：打点、分析、暂停/恢复、停止
- 页头显示配额摘要（如“运行中 2/5 · 已结束 1”）；没有任务时显示三步引导（选进程 → 预热后打“基线” → 每轮操作后打点）

**任务结束后**：卡片转入下方“已结束（N）”分组并收成一行，提供“查看分析”（跳转分析页并选中该任务）、“同配置再测”（沿用进程、指标、周期与备注新建任务；按进程名查找运行中的进程，不含本程序自身，找到多个或找不到时由用户在进程框中选择）和“关闭”（移除卡片）；分组标题行“清除全部”一次移除全部已结束卡片（数据仍保留在分析页）。被测进程崩溃或退出等非用户停止的情形，弹出显眼的提示条，窗口在后台时补一条托盘气泡。

**更新频率**：根据采集周期实时更新

**优先级**：P0（必须）

#### 2.1.6 采集失败语义
**需求描述**：采不到的指标不能被记成0，否则会被误读为真实数据

**功能要求**：
- 某指标本周期无法采集时，该指标不写入数据（留空），其他指标照常记录
- 任务卡片将该指标显示为“不可用”，并提示一次原因（每个指标每个任务只提示一次）
- 未以管理员运行时，对更高权限进程只有“独占物理内存（USS）”无法采集；以管理员身份运行可采集全部指标
- 其他会话的进程（如系统服务）的GDI/USER对象数显示“不支持”（提权也无法采集，与权限不足区分）
- 分析图表与CSV对缺失值按空处理
- 进程不存在，或PID已被另一个进程复用（比对进程创建时间）时，任务以“进程已终止”结束

**优先级**：P0（必须）

#### 2.1.7 打点与测试备注
**需求描述**：为长时间监控中的关键操作留下时间标记，便于在历史曲线上对应到具体测试动作

**功能要求**：
- 运行中的任务可随时打点：卡片“打点”弹出输入框（显示进程与记录时刻），默认名称按序列给出——尚无基线时为“基线”，之后为“第 N 轮”，最多40字；名称为“基线”的打点即为基线（每个任务至多一个）
- 免弹窗打点：托盘右键菜单“打点”（一个任务时直接打，多个任务时可选全部或其中一个）与全局快捷键（默认 Ctrl+Alt+M，可在设置页修改或清空）都直接用默认名称在当前时刻打点，结果用托盘气泡确认；快捷键被其他程序占用或写法不对时不可用，设置页说明原因，不影响其他功能
- 暂停/恢复任务时自动写入“暂停”“恢复”系统打点
- 打点时间取点击“打点”（或按下快捷键）的时刻，名称为空时不能添加；分析页趋势图上显示为带编号徽标的竖线，在图上右键可“在此处打点 / 设为基线 / 重命名 / 删除”
- 打点随明细CSV写入末列“打点”，并决定打点区间表与摘要CSV的分段
- 测试备注在创建任务时填写，显示在任务卡片、分析页任务列表与报告中

**推荐用法**：选进程 → 使用默认预设 → 预热到稳定后打点“基线” → 每轮操作后打点（手在被测程序上时用快捷键）→ 在分析页看判定摘要与打点区间 → 导出报告

**优先级**：P1（重要）

### 2.2 分析功能（历史数据）

#### 2.2.1 数据持久化
**需求描述**：所有监控数据自动保存到本地数据库

**功能要求**：
- 使用SQLite数据库存储，启用WAL（Write-Ahead Logging）模式提升读写并发稳定性
- 采用批量保存接口写入数据（当前批大小配置为1条，即每次采集立即落盘，以保证分析页能实时看到最新数据）
- 数据落库失败时自动重试：采集缓冲保留待重试数据（上限1000条，超出丢弃最旧数据），连续失败达到阈值时提示用户一次（v1.2.0）
- 自动管理数据库连接
- 支持长时间监控数据存储

**优先级**：P0（必须）

#### 2.2.2 任务与范围选择
**需求描述**：在“分析”页选择一个有数据的任务和时间范围，一次看全该任务的所有指标

**功能要求**：
- 显示所有包含数据的任务（含运行中和已结束）；下拉项显示进程名、PID、开始时间、时长、备注（运行中任务标注“运行中”并持续更新时长）；悬停显示完整信息；从监控卡片“分析/查看分析”跳转时自动选中该任务
- 范围：自基线（无基线时等同全部）/ 10分钟 / 1小时 / 6小时 / 24小时 / 全部（默认）/ 自定义；范围锚定该任务最后一次采样，停止已久的任务仍能看到其最后一段数据；“自定义”由趋势图下方概览条拖动选区产生
- 视图：小倍数（每个指标一张图）| 叠加Δ%（各指标相对基线的百分比画在一张图上）；横轴 绝对时间 | 相对时间（以基线或首个点为原点）
- 所选任务仍在运行时，页面可见期间自动刷新，刷新间隔随数据量自适应；鼠标悬停或拖动图表、窗口最小化时跳过；任务结束后自动同步最终数据
- 所有数据加载都在后台执行，较慢时显示加载条，大数据量任务操作时界面不卡

**优先级**：P0（必须）

#### 2.2.3 判定摘要
**需求描述**：每个指标一行结论，回答“哪些指标在涨、涨多快、依据是什么”

**功能要求**：
- 列：指标 / 基线 / 当前 / 较基线（Δ与百分比）/ 每轮均增 / 增速±置信区间 · R² / 末段趋势 / 判定 / 上限占比（GDI/USER对象数相对系统上限10000）
- 表格上方的依据行写明统计口径，如“基线 16:37:33 起 · 2小时15分 · 8,100 点”
- 基线：基线值取基线打点后5个样本的中位数；存在基线时统计、回归与判定只用基线之后的数据（预热段不算进泄漏）
- 增速门槛：至少30个点、且跨度不短于 max(10分钟, 30×采集周期) 才给增速，否则显示“数据不足（已采 X / 仅 N 点）”且整行置灰；增速按跨度用“/分”（不足1小时）或“/小时”
- 判定：持续上涨（斜率为正、R² ≥ 0.8、置信区间不含0、拟合增量 ≥ 值域的5%）/ 平稳 / 波动 / 数据不足
- 累计类指标（CPU时间、页面错误、上下文切换、I/O次数与字节）不外推增速，显示平均速率（每秒）并标“累计量”；峰值类指标显示“抬升 N 次”
- 点击某行把该指标设为焦点，打点区间表、采集明细与概览条随之切换

**优先级**：P0（必须）

#### 2.2.4 趋势图
**需求描述**：以图表形式展示各指标随时间的变化，并标出操作节点与采集中断

**功能要求**：
- 小倍数：每个指标一张图，共享横轴，悬停任一张时各图十字线与读数联动；按宽度排1–2列
- 水位类指标画中心线 + 最小/最大值带（按时间分桶，保留波峰波谷）；累计类指标画每秒速率
- 打点以带编号徽标的竖线叠加在每张图上；右键编辑打点（见2.1.7）
- 采集空洞（相邻采样间隔超过2.5个采集周期，如暂停、休眠）处曲线断开并画阴影
- Y轴自动缩放，按量级自适应显示KB/MB/GB/TB，刻度按显示单位取整，计数类指标使用整数刻度；曲线平直时设纵轴最小跨度（速率曲线按数值的5%），避免微小抖动被放大成满幅波动
- 底部概览条显示焦点指标全程走势，拖动或拉伸选区即按选区重新统计
- 配色跟随深浅色主题

**优先级**：P0（必须）

#### 2.2.5 打点区间与采集明细
**需求描述**：按打点把焦点指标切成各轮，逐轮看增量是否收敛；需要时查看逐条原始数据

**功能要求**：
- 打点区间表（默认子视图）：列为 区间 / 时长 / 起值 / 终值 / Δ / 速率 / 峰值 / 与上轮差；点击一行把趋势图缩放到该区间
- 采集明细：时间、格式化值、较上次、较基线；“原始值”列可从“更多”菜单按需显示；只显示最近若干条并标注“显示最近 N 条 / 共 M 条”（导出不受限制）；按时间倒序（最新在前）；禁止编辑

**优先级**：P1（重要）

#### 2.2.6 任务对比
**需求描述**：把两次测试（如修复前后）放在一起比较

**功能要求**：
- 工具条“对比任务”打开对比卡片，选择第二个任务
- 同一指标两条曲线叠加，各自画相对起点（基线或首个点）的变化量，横轴对齐为相对时间
- 下方并排两张分轮增量表
- 对比任务没有该指标或读取失败时给出说明

**优先级**：P1（重要）

#### 2.2.7 任务数据管理
**需求描述**：用户可在分析页手动清理不再需要的任务数据，应用也可选择性地在启动时自动清理过期数据（v1.2.0）

**功能要求**：
- 分析页“更多”菜单提供“删除此任务数据”，二次确认（焦点在“取消”）后删除该任务及其全部数据点与打点
- 任务运行中时删除不可用（需先停止任务），避免删除正在写入的数据
- 设置页的数据库清理与压缩与运行中任务、导出互斥：有任务运行或导出进行中时不可用，清理期间不能新建任务或开始导出
- 支持可选的启动自动清理：通过配置项设定数据保留天数，默认0表示禁用；启用后仅清理已停止且早于保留期限的任务及其数据点，且保证在孤儿任务状态校正完成之后执行，避免误删刚异常退出的任务

**优先级**：P2（增强）

### 2.3 报告导出功能

#### 2.3.1 导出入口

#### 2.3.2 报告三件套
**需求描述**：同一目录、同一基名的三个文件

**功能要求**：
- `<任务>_报告.png`：标题（进程 · PID · 备注 · 指标）、信息行（范围 · 时长 · 采集间隔 · 点数）、每个指标一行结论、多指标小倍数图与脚注，与界面同一绘图管线

**优先级**：P0（必须）

#### 2.3.3 数据完整性
**需求描述**：确保导出的数据完整准确

**功能要求**：
- 明细CSV导出任务的全部采集记录（含全部已选指标），不受界面明细表条数限制
- 列头本身标注指标名称与单位，无需额外的单位列

**优先级**：P0（必须）

## 6. 数据模型

### 6.1 监控任务（MonitorTask）
自v1.1.0起支持多指标监控，原单值 `metric_type` 字段已改为字符串列表 `metric_types`：
```python
{
    "task_id": "UUID字符串",
    "pid": "进程ID",
    "process_name": "进程名称",
    "metric_types": ["指标类型1", "指标类型2", "..."],  # 指标类型列表，支持多指标
    "interval": "采集间隔(秒)",
    "start_time": "开始时间",
    "end_time": "结束时间(可空)",
    "status": "running | stopped",
    "note": "测试备注(可空串)",
    "sample_count": "已采集次数(同一周期多指标算一次)",
    "last_sample_at": "最后一次采样时间(可空)"
}
```

### 6.2 数据点（DataPoint）与打点（Marker）
数据点带 `metric_type` 字段，标记该数据点归属于任务的哪一项指标；采集失败的指标不产生数据点：
```python
{
    "task_id": "所属任务ID",
    "timestamp": "时间戳",
    "value": "指标值(浮点数)",
    "metric_type": "指标类型"
}
```
打点用于在曲线上标注测试动作：
```python
{
    "task_id": "所属任务ID",
    "timestamp": "打点时间",
    "label": "名称（默认序列：基线 / 第 N 轮）",
    "kind": "user | baseline | pause | resume"  # 用户打点 / 基线（每任务至多一个）/ 暂停、恢复系统打点
}
```

### 6.3 数据库结构与迁移

**表结构（Schema v4）**：
- `tasks` 表：`metric_type` 列存储 JSON 数组文本（如 `["memory_rss","cpu_percent"]`），对应 `metric_types` 字段；另有 `note`、`sample_count`、`last_sample_at`、`create_time`（被监控进程的创建时间，用于识别PID复用）。分析页按 `sample_count > 0` 判断“有数据的任务”，避免逐任务统计数据点
- `data_points` 表：`task_id`、`timestamp`、`value`、`metric_type`（允许为 NULL，兼容升级前的历史数据），仅保留一个复合索引 `(task_id, metric_type, timestamp)`，覆盖按任务/指标/时间范围的过滤、排序与首尾点查询
- `task_markers` 表：`id`、`task_id`、`timestamp`、`label`、`created_at`、`kind`，索引 `(task_id, timestamp)`
- 时间戳一律以 ISO 文本存储和比较
- 外键约束未启用，删除任务时手工级联删除其数据点与打点
- 每个数据库连接开启时统一设置 `WAL` 日志模式、`busy_timeout=5000ms`、`synchronous=NORMAL`，提升并发读写下的稳定性（v1.2.0）

**自动迁移机制**：
- 数据库使用 `PRAGMA user_version` 标记 Schema 版本（当前为 v4），启动时低于当前版本则按 v0→v1→v2→v3→v4 链式迁移：
  - v0→v1：补充 `data_points.metric_type` 并按任务原有指标回填，`tasks.metric_type` 由裸字符串转换为 JSON 数组
  - v1→v2：把 `memory_vms`、`memory_pagefile` 并入 `memory_private`，同一时间戳的重复数据点去重
  - v2→v3：`tasks` 增加 `note`、`sample_count`、`last_sample_at` 并回填；新建 `task_markers`；清理孤儿数据点、回填 NULL 的指标类型；索引收敛为 `(task_id, metric_type, timestamp)`
  - v3→v4：`tasks` 增加 `create_time`，`task_markers` 增加 `kind`
- 迁移前先对旧库做一次 WAL checkpoint，再将数据库文件备份为同目录下的 `monitor.db.bak_v{原版本}`，原始数据永不删除
- 整条迁移链在同一个显式事务中执行，任一步失败整体回滚；失败后先从备份文件还原并重试一次，两次仍失败则将损坏的数据库文件改名保留（形如 `monitor.db.broken_时间戳`）、新建空库
- 迁移结果分三种明确状态，分别对应不同的主界面提示（v1.2.0）：
  - **迁移失败、旧数据保留**（`migration_failed`）：迁移失败且旧数据仍在原库（通常已从备份还原；还原与改名都失败时旧库原样保留、不标记新版本，下次启动重新迁移），提示用户本次会话新数据无法保存，需重启重试
  - **数据已重置**（`data_reset`）：还原备份也失败，损坏库已改名保留，应用以新建空库运行，提示用户历史数据已移至 `monitor.db.broken_*`
  - **迁移已中止**（`backup_aborted`）：迁移前备份本身失败（如磁盘空间不足），直接中止迁移、旧库原样保留未做任何改动，提示用户释放磁盘空间后重启
- 整个迁移流程每次应用运行只尝试一次，避免同一进程内因反复实例化数据库对象而重复触发备份
- 每次启动另外执行：校正遗留的“运行中”任务、重算采样计数为0但有数据点的任务（回退旧版本再升级后的兜底）

## 7. 系统流程

### 7.1 创建监控任务流程
```
选择进程（或输入PID）→ 确认指标（默认泄漏排查预设）→ 设置周期、填写备注
    ↓
点击"开始监控"（同PID已在监控则二次确认）
    （勾选"等待进程启动后自动开始"时：先显示等待占位卡，按进程名每秒查找，出现后自动走下面的流程）
    ↓
检查运行中任务数量限制与数据库维护状态
    ↓
创建监控任务(QThread)，任务行落库
    ↓
按单调时钟截止时间循环：采集 → 落库 → 更新卡片
    （采不到的指标留空并提示不可用）
```

### 7.2 停止监控任务流程
```
用户点击"停止"并确认
    ↓
置停止标志并唤醒工作线程（界面不等待）
    ↓
工作线程内：保存剩余数据 → 写入已停止状态 → 发出停止信号
    ↓
卡片转入"已结束"分组（查看分析 / 同配置再测 / 关闭），释放任务线程对象
```

### 7.3 分析流程
```
监控卡片"分析/查看分析"跳转，或切换到分析页（默认"全部"范围）
    ↓
加载有数据的任务列表（运行中任务标注"运行中"）
    ↓
选择任务与范围 → 后台对每个指标并行查询：基线、聚合与判定、分桶与最小/最大值带、空洞、打点区间
    ↓
填充判定摘要表、小倍数趋势图（打点竖线、空洞阴影）、打点区间表与采集明细
    ↓
任务运行中：页面可见时自动刷新；右键编辑打点后静默重查
```

### 7.4 报告导出流程
```
"导出报告 ▾" → 选择保存位置（默认 <任务>_报告.png，已存在则确认覆盖；清理数据库进行中则直接提示）
    ↓
界面线程离屏渲染报告图片 → 后台线程流式读取数据点与打点
    ↓
写入同目录临时文件：报告图片、明细CSV（元数据、已运行秒数、空洞空行）、摘要CSV
    ↓
成功：逐个替换目标文件，提示并可打开文件夹；取消/失败：删除临时文件
```

### 7.5 关闭窗口流程
```
关闭窗口
    ↓
设置了"关闭时最小化到托盘" → 隐藏到托盘，监控继续
    ↓
有运行中任务 → 询问：停止并退出 / 最小化到托盘 / 取消
    ↓
停止并退出：等待全部任务收尾落库 → 清理后台线程 → 退出
（系统注销/关机时跳过询问，直接退出）
```

## 8. 异常处理

### 8.1 进程不存在
- **场景**：用户输入的PID不存在或无法访问
- **处理**：显示错误提示，禁止创建任务

### 8.2 进程已终止
- **场景**：监控过程中进程意外终止，或PID已被另一个进程复用
- **处理**：自动停止监控任务，保存已采集数据；任务卡片保留并标为已结束，弹出提示条（窗口在后台时补托盘气泡）

### 8.3 数据库异常
- **场景**：数据库文件损坏或权限不足
- **处理**：显示错误信息，尝试重新初始化数据库
- **场景**：单次数据保存失败（磁盘瞬时繁忙等）
- **处理**：自动保留待落库数据并在下一采集周期重试，不立即丢弃；连续失败达到阈值时提示用户一次（v1.2.0）
- **场景**：旧版本数据库升级迁移失败（详见6.3节）
- **处理**：自动从迁移前备份还原并重试一次；三种最终结果对应三种明确的主界面提示——迁移失败、旧数据保留（提示重启重试）、数据已重置（提示历史数据已移至`.broken_*`文件）、迁移已中止（提示释放磁盘空间后重启）（v1.2.0）

### 8.4 任务数量超限
- **场景**：用户尝试创建第6个运行中的监控任务
- **处理**：显示警告提示，禁止创建

### 8.5 指标不可用
- **场景**：权限不足（如未以管理员运行时采集更高权限进程的独占物理内存（USS））、进程正在退出，或指标对该进程不适用（其他会话进程的GDI/USER对象数）
- **处理**：该指标不写入数据，卡片显示“不可用”并提示一次原因（权限不足时建议以管理员运行）；其他指标不受影响

### 8.6 更新包无法校验
- **场景**：新版本的安装包缺少SHA-256摘要，或下载后校验不一致，或下载地址不在官方域名内
- **处理**：不安装；缺少摘要时提示“请前往发布页手动下载”，校验不一致时删除已下载文件并报错

## 附录：术语表

| 术语 | 解释 |
|------|------|
| PID | Process ID，进程标识符 |
| RSS | Resident Set Size，工作集内存 |
| 私有字节 | Private Bytes，进程独占的已提交内存（PrivateUsage，等同任务管理器"提交大小"；psutil 的 vms / pagefile / private 在 Windows 上数值相同） |
| GDI/USER对象 | Windows界面资源：GDI对象（画笔、位图、字体等绘图资源）与USER对象（窗口、菜单、光标等），数量持续增长通常意味着界面资源泄漏 |
| 打点 | 在监控过程中以当前时间为任务添加的带名称的时间标记；默认序列为“基线 / 第 N 轮”，暂停/恢复时自动写入系统打点 |
| 基线 | 被测程序预热到稳定状态时打下的特殊打点（每任务至多一个）；基线值取其后5个样本的中位数，统计与判定只用基线之后的数据 |
| 判定 | 分析页对水位类指标给出的趋势结论：持续上涨 / 平稳 / 波动 / 数据不足（门槛与规则见2.2.3） |
| 空洞 | 相邻两次采样间隔超过2.5个采集周期的时段（暂停、休眠等），图上断线加阴影、明细CSV插空行 |
| USS | Unique Set Size，进程独占、不可与其他进程共享的物理内存 |
| CPU使用率 | 进程占用CPU的百分比 |
| 句柄 | Windows系统资源的引用 |
| IO | Input/Output，输入输出操作 |
| Qt信号槽 | Qt框架的事件通信机制 |
| QThread | Qt的线程类 |
| SQLite | 轻量级关系型数据库 |
